PROLOGUE

Why the manuscript's metric is the wrong one

the problem, stated plainly

The manuscript measures distribution shift like this. For a trial with matched object A and oddity B, run both through the pretrained encoder, find the single training image C whose features are closest to both, and call the shift ½[d(A,C) + d(B,C)], with d the ℓ₁ distance in the encoder's raw feature space.

Three things are wrong with that number, and each one is a way for it to be large without the trial being far from the training data.

1 · It contains the trial's own difficulty — the triangle inequality, spelled out

For any way of measuring distance that deserves the name, the direct route between two points is never longer than a detour through a third: d(A,B) ≤ d(A,C) + d(C,B). That is the triangle inequality, and it is part of the definition of a distance — L1, L2 and angular distance all obey it. Halve both sides: ½[d(A,C) + d(C,B)] ≥ ½·d(A,B).

Now look at what the shift is: the smallest value of the left-hand side over every training image C. Minimising over C can make the left side as small as the training set allows — but it can never push it below ½·d(A,B), because no C does. The floor is reached only if some training image sits exactly on the straight path from A to B. Every real training image sits off that path, and the shift is the floor plus however far off it the best one is:

shift = ½·d(A,B) + excess, excess ≥ 0 └── the task's own difficulty └── the only part that is about the training set

The oddity task is decided by d(A,B) — how different the two objects look to the encoder. So a trial whose objects are very different is guaranteed a large "shift" whatever the training set contains, and a trial whose objects are nearly identical is guaranteed a small one. The picture makes it obvious: for L2, the set of points C with a given value of d(A,C)+d(B,C) is an ellipse with A and B as its foci, and the shift is the smallest ellipse that touches a training image. Move A and B apart and every ellipse grows, the training images included.

Does cosine, or L2, get around it?

No. The bound is a property of every metric, not of L1. On the same 2,019 trials, with the shift recomputed under three distances:

Cosine is slightly worse. (Strictly, 1 − cosine is not a metric — its square root, the chord length, is — so it can violate the bound by a small slack; on ShapeNet it holds in 96.5 % of trials rather than 100 %. That slack does not help.) Normalising the features fixes fault 2, the norm, and leaves fault 1 exactly where it was.

What does help is changing the form: give each object its own nearest training image, ½[minC d(A,C) + minC′ d(B,C′)], and there is no shared C, so no bound. In the encoder's space that takes r(shift, d(A,B)) from 0.78 to 0.66 — still high, no longer a theorem but a property of that space, where both quantities scale with how the encoder spreads images out. Leaving the encoder's space finishes it: the oddity-blind form on geometric descriptors gives +0.45 on ShapeNet and −0.36 on ShapeGen (panel D). And the within-trial design of Act 4 removes the floor a third way: d(A,B) is a constant across the twelve models of a trial, so whatever it contributes is the same in every column and vanishes under centring.

2 · It is mostly the size of the feature vector

In raw feature space, the ℓ₁ distance between two vectors is dominated by how long they are. The audit found r(shift, ‖φ‖₁) = 0.95 for ResNet-50 and 0.89 for DeiT-III (panel B), and for DeiT the shift adds nothing to the norm in a nested regression (χ² = 0.3, p = 0.59). Feature norm is a property of how the encoder responds to the test image, not of where the training set is.

3 · It is validated against itself

The paper's test-time proxy ŝ = 1 + εm is the encoder's margin. The "empirical shift" it is validated against is computed in that same encoder's features. Both numbers come out of the same box — and the encoder's own d(A,B), which the shift is bounded by, is its margin, near enough: r = +0.57 for DINO ViT-B over all 2,019 MOCHI trials, +0.72 for DINOv2-L on ShapeNet (panel C). A correlation between ŝ and the shift is what any shared property of the box would produce, with no distribution shift required.

The consequence

A "shift" that goes up when the objects are easy to tell apart, goes up when the encoder's activations are large, and is read off the same encoder whose margin it is meant to explain, is a measure of how the encoder responds to the trial. It correlates with the margin because both are the encoder's response. That is why, on the one dataset where we have models that did and did not see each training set, the metric tracks the one that did not (panel D) — and why it only behaves after two-way centring (Act 7), which strips out every trial-level and category-level thing it was tracking.

What a right metric has to do

Three things, one for each fault. Be computed without the encoder, from the stimuli and the training set alone. Never difference A and B — average a per-image quantity over the trial, so the task's decision variable cannot enter. And be unable to predict the pretrained margin: a model that never saw the training set is the control, and a valid shift measure has to leave it flat. The rest of this page is the search for a measure that does all three; coverage in voxel space (Act 7) is where it ends up.

The original number is not a bad estimate of distribution shift. It is a good estimate of something else — the encoder's ease on the trial — wearing the wrong name.
ACT 1

Build a ruler with no parameters

where belief stood · not yet earned

The manuscript's distribution-shift metric is model-based twice over. The trial-to-training distance is a nearest-neighbour search inside the pretrained encoder's own feature space, and the test-time proxy is that same encoder's oddity margin.

The prologue says why that fails. Here is what we built instead.

MOCHI's ShapeNet and ShapeGen trials are rendered from known 3D assets. Stimulus geometry is known, not inferred. So the question was whether a shift measure computed from geometry alone — no encoder, no learned parameters — could stand in for the circular one.

What we measured

Every object's model_normalized.solid.binvox (a 128³ solid voxelisation), reduced to descriptors with no fitted parameters: a 57-d rotation-invariant shape distribution, raw occupancy grids at 8³, 16³ and 32³, seven numbers from the bounding-box JSON, and a handful of pose-referenced silhouette statistics. Cosine distance on z-scored, L2-normalised descriptors.

The estimator

Oddity-blind, hub-robust, norm-free. Average a per-image distance over all a trial's images — never difference them — because the shared-neighbour form minC ½[d(A,C)+d(B,C)] is bounded below by half the trial's own decision variable d(A,B), and difficulty leaks in. Mean over the 50 nearest training objects, not a single argmin. A ruler that training cannot reshape.

The design that would matter later

Twelve models, one per ShapeNet category, each fine-tuned from the same DINOv2 on that category alone. Every trial goes through all twelve. The trial's images, its objects, its difficulty and the base model's margin are identical across the twelve — only the training set differs. We didn't fully appreciate what this bought us until Act 4.

Descriptor A — 57-d rotation-invariant (d57)

  1. Parse the binvox: header lines dim / translate / scale / data, then run-length pairs (value, count); raw order is x-major, then z, then y, so transpose (0,2,1) to xyz.
  2. Take occupied voxel coordinates. Subsample 4,096 (RNG seed 0). Centre on centroid; scale to unit RMS radius.
  3. D2: 200,000 random point pairs, histogram of pairwise distances, 32 bins on [0, 4], density-normalised.
  4. Shell: histogram of distance-to-centroid, 16 bins on [0, 3], density.
  5. 9 scalars: eigenvalues of the point covariance normalised to sum 1 → elongation λ₂/λ₁, flatness λ₃/λ₁; compactness n_surface / n_vox^(2/3) where surface voxels are occupied with an unoccupied 6-neighbour; norm_vol n_vox / rms³; convexity norm_vol / hull_volume (ConvexHull of the normalised points); r_mean, r_std (of the shell distances); d2_mean, d2_std (of the D2 distances).

Descriptor B — raw occupancy grids (voxel8/16/32)

Reshape the 128³ grid to (N, 128/N, N, 128/N, N, 128/N) and take the mean over the three block axes → N³ occupancy fractions. Pose-sensitive by construction. 512 / 4,096 / 32,768 dims.

Descriptor C — bounding box (bbox, 7-d)

From model_normalized.json: sort extents descending and divide by the largest → [e₁, e₂, e₁·e₂, vol^(1/3), |centroid − box centre| / |diag|, log₁₀ numVertices, log₁₀ vol].

The estimator (blind_k50)

z-score every dimension with the BANK's mean and sd (sd < 1e-9 → 1) L2-normalise rows; D(t, b) = 1 − t·b (cosine distance) per test object: mean of its 50 smallest D to the category bank per trial: mean of that over every image's object (oddity-blind)

Averaging over all images, never differencing them, is what keeps trial difficulty out: the shared-neighbour form min_C ½[d(A,C)+d(B,C)] is bounded below by ½·d(A,B), the task's own decision variable.

ACT 3

Two things were wrong

where belief stood · falling

Two separate problems, found at different times. The first is the one everyone had already complained about. The second we only fully measured when writing this page.

Problem 1 — the shift was entangled with the trial's own difficulty

The Act 2 shift is the manuscript's Eq. 1–3 with the feature swapped: mini ½[d(A,Ci) + d(B,Ci)]. By the triangle inequality that is bounded below by ½·d(A,B) — the dissimilarity of the two objects, which is the oddity task's own decision variable. We knew it was a bound. We did not know how tight.

The shapegen headline from Act 2 is withdrawn. "Dissimilar objects are easier to tell apart" is true and uninteresting.

Problem 2 — the control tracks it too

We had a natural control: the pretrained DINOv2, which never saw any of the twelve fine-tuning sets. A valid shift measure should not predict its margin. It did.

The caption we wrote at the time says it exactly: "pooled across trials, the pretrained margin tracks geometric shift more strongly than the fine-tuned one, though it cannot possibly depend on these training sets. The pooled correlation is therefore a stimulus property, not a distributional effect."

Objects that are geometrically far from every training set are also, plausibly, just hard — for every model. The pooled figure has two things in it, training exposure and object atypicality, and cannot separate them. Act 2's beautiful curve was real, but it was not yet evidence about training.

Entanglement is fixed by the blind metric. Atypicality is not — the pooled relationship is a property of the stimuli. We needed a design in which the stimuli could not vary.

ACT 4

Remove trial difficulty by design

where belief stood · rising, and now earned

Two fixes, and from here on both are always in place. The oddity-blind estimator (Act 1's recipe) removes the entanglement. The twelve-model design removes atypicality: within a trial, the pretrained margin is a constant — variance ~10⁻³⁵ — so centre or rank within trial and the control becomes a flat line by construction. The fine-tuned margin still falls.

ACT 5

One question too many

where belief stood · falling — for the wrong reason

Look at the rank curve again. It is mostly a step: the on-category model sits far above the other eleven, which are roughly flat. So we asked a second question. Holding category membership fixed, does graded geometric distance still predict the margin?

That is the within-category row: keep only the model trained on each trial's own category. One point per trial, n = 706.

We searched for a metric that would work there

A hill climb over 1,895 candidates — eight representations, twenty-odd estimators, twelve trial-level metrics — with the within-category margin advantage as the objective, fifty repeats of five-fold cross-validation over trials, and a permutation null on the maximum statistic. In-sample the winner reached |r| = 0.184 with a corrected p of 0.001. Out of sample it scored 0.113 against 0.133 for the fixed baseline, losing in 72% of repeats.

There is no single model-free metric that makes the within-category relationship strong. About 0.13 is the ceiling for that question in these data.

The causal analysis said the same thing

Remove the on-category model from each trial and the per-trial slopes go to the null (mean −0.004, p = 0.29). Remove the diagonal from the transfer matrix and the 144 cell means go from r = −0.364 to −0.024. Within this dataset the effect is coverage — did you train on this kind of object — with at most a small graded component beyond it.

This is where it got sad. Every follow-up figure was about the second question, and every one of them came back weak. It started to feel like the whole thing had not worked.

ACT 6

What actually stands

where belief stood · settled

The pessimism was half right. The other half was a conflation: a weak answer to the second question got read as a weak result overall, when the first question — the one the paper needs — had already been answered strongly in Act 4.

Question 1 · what the paper needs
Does the margin respond to the training distribution, measured model-free, with a control that cannot be gamed?
Yes. 84% of trials, permutation p = 10⁻⁴, 25 accuracy points, d = 1.4, control zero by construction, robust to descriptor, estimator, centring and binning, and to a 1,895-metric search.
Question 2 · a finer follow-up
Beyond category membership, does graded distance within a category's training set predict the margin?
Barely. r ≈ −0.10, ceiling ≈ 0.13 after the search; the coverage metric of Act 7 does not change this once category is centred. Not resolvable with twelve categorical training sets — the dose range among off-category sets spans a factor of about five, where the literature that finds graded laws spans orders of magnitude.

The every-trial-×-every-model figure from Act 2 is not wrong either: it uses the blind metric, so it is free of entanglement, and it contains a training effect plus an atypicality effect that the within-trial design separates. The shapegen encoder comparison was wrong, and it is gone. Question 2's honest answer is a scope condition worth stating plainly — not a reason to doubt Question 1.

Robustness, briefly

If we want Question 2 anyway

Not a better metric — the search settled that. A different design. Convert the categorical factor into a dose: fine-tune on mixtures with a varying share of the test category (0, 1, 5, 25, 100%), or on the test category with the k most similar objects held out, sweeping k. Either gives an x-axis that spans orders of magnitude, and the same within-trial machinery applies unchanged. A second seed per category would also tell us whether 0.13 is the phenomenon or the noise floor.

Representational support is set by the training distribution. We can move it by moving the training data. We can measure the training data's relation to the stimulus without touching the model. The graded form is the natural follow-up, and the tools for it are built.

ACT 7

Coverage, not distance

where belief stood · rising — new, split-half validated, with one honest limit

Every estimator so far asks how far the nearest training objects are. A different question: how much training mass is near the object at all. Count the category's training objects inside a fixed cosine radius ε, take −log(1 + count), average over the trial's images.

The difference is the ceiling. Under a distance measure, an object that is far from every training set keeps getting farther, and that between-trial variance is exactly the atypicality that leaked into the pooled row. Under coverage, "no training objects nearby" is the most shift there is; nothing beyond it counts.

Three metrics are compared side by side from here on: coverage, the oddity-blind knn_mean, and the original — the manuscript's own per-category DINOv2-ℓ₁ distance, read straight from each category's results file. The pretrained control is always drawn on its own axis; it was compressing the fine-tuned range when shared.

The on-category row, thought through

This is the row that was weak under distance — one point per trial, only the model trained on the trial's own category, n = 706 — and the first coverage pass made it look rescued: r = −0.118, binned −0.78, a clean-looking curve. Here it is for all three metrics, with the control on its own axis.

So is the coverage step a within-category graded effect? No. The more-than-100 group is entirely airplane, bench, car, lamp, telephone and watercraft — geometrically homogeneous categories in which hundreds of training objects sit within ε of almost any member. Chair, table, cabinet, sofa, display and loudspeaker never reach 100, despite having the largest banks, because their shapes are diverse. The step is a difference between categories.

Centre within category and it is gone: r(step, margin) = +0.030, p = 0.42; among the six categories that contain both groups, the mean within-category difference is +0.007, positive in four of six (sign test p = 0.69). Same for the margin advantage. This is exactly what happened to the distance metric in Act 5, for the same reason: in the on-category row "which category" and "which training set" are the same variable, and category identity carries everything.

What the on-category row can honestly say is a category-level sentence with n = 12: models fine-tuned on homogeneous categories produce larger margins on those categories. That may well be true and is worth a line, but it is not the graded within-category relationship Question 2 asks for, and coverage does not deliver it either.

Coverage is the better ruler — cleaner pooled row, stronger within-trial effect, survives category centring — but Question 2 still has the same answer. What moves within a trial is which training set the model saw; how much of it resembled the object matters between categories, not within one.

Caveat, stated once: this is 14 estimator variants tried in a day, and the hill climb taught us what in-sample winners are worth. The reasons to take it seriously are that it is not a spike — it holds across ε from 0.03 to 0.20, on a rotation-invariant and a pose-sensitive descriptor, in every one of 20 held-out halves — and that the gain is qualitative: a control passing where it failed before. The reason not to over-read it is the paragraph above.

To choose ε honestly

Split trials in half, pick the ε with the largest within-trial |r| on one half, report everything on the other. The soft version −log Σi exp(−D[x,i]/ε) behaves like knn_mean, which shows the hard cut-off is doing the work.

ACT 8

Images, not objects

where belief stood · a hypothesis tested, and not supported — but informative

Every metric so far compares objects: is there a training shape like this shape? The hypothesis behind this act is that encoders learn view-conditioned appearance, so the training distribution that matters is over images — shape × viewpoint — and coverage should be counted there: is there a training image like this image?

The training set makes this testable without a renderer. Every training object was rendered from the same 15 fixed cameras (a Fibonacci sphere at radius 2), with the pose stored per image. So we can project each object's voxels from those cameras to a depth + silhouette map, and get a model-free descriptor of "this shape, seen from this angle" for all 313,275 training images. For the MOCHI images the camera isn't stored, but the object is known, so the pose is recovered by matching the image's silhouette against voxel projections over 800 candidate cameras — mean IoU 0.856 over 2,257 images.

Read against the hypothesis: if the models' support were view-conditioned, a MOCHI image taken 21° off the training grid (the median) would have less support even for a well-covered shape, and image-level coverage at the actual view should predict the margin better. It predicts it worse, on every descriptor variant (silhouette only, depth only, pooled to 16×16 and 8×8) and every ε. What predicts the fine-tuned margin is whether the training set contained the shape, evaluated from any of the views the model was trained at. Within the ~25° gaps of the training grid, the fine-tuned support behaves as view-invariant — which is what a multi-view contrastive objective, pairing the same object across its 15 views, was built to produce.

Two honest limits. The gaps are small: no MOCHI camera is more than ~25° from a training camera, so this says nothing about 60° or 120°. And image-space coverage fails the pooled control in every variant (+0.06 to +0.16, the wrong sign): something about silhouette/depth similarity tracks the base model's ease. Object-level voxel coverage remains the only pooled-clean measure. The view-only shift — angular distance to the nearest training camera — is null (r = −0.026), as it must be when every trial sits inside a uniform view grid.

The view-conditioned metric was the right thing to build and the right thing to test. Its answer is that these models' support is for shapes, not for shapes-from-angles — at least across the angles they were trained on.
Recipe · depth-from-voxels, pose estimation, image-level coverage

ACT 9 · 19–20 SEP

Change the training data

where belief stood · the margin follows the training set inside a category too — shown by training new models, not by scoring old ones

Everything before this act used the twelve category models we were given. Inside a category that leaves one training set per category, so "far from the chair training set" and "an unusual chair" are the same fact and no estimate can separate them. The only way through is to train new models on chosen subsets of a category, so that the training set varies while the test trial stays fixed. This weekend we did that, twice.

The first round showed nothing. Remove the ten training objects nearest a group of test objects (about 10 % of a 2,000-object set), fine-tune, and measure on the 76 MOCHI chair trials: the margin changed by 0.001, against a run-to-run difference of 0.02 between any two models trained on different data. Two reasons, both about the instrument. The training pipeline draws the same 20,000 image triplets per epoch whatever the bank size, so removing 200 of 2,000 barely changes what the model sees — and 100 chairs train it as fully as 2,000 do. And MOCHI's chair trials were selected to be hard for the pretrained model, so inside the category the unusual chairs are the easy trials. Also learned: our pipeline does not reproduce the collaborator's original models (0.155 against 0.241 on the same chairs), so nothing we train is compared to the original twelve.

The second round worked. The lead's design: we know category membership moves the margin, so find categories within the category. Cluster the chairs on their 3-D shape, keep the three most separated kinds (tall narrow-backed, wide armchair-like, round-backed and office), split each in half, fine-tune one model per kind on 25, 50 or ~100 of its training half, and build 882 hard oddity trials from the held-out halves — hundreds of trials instead of 76, with no MOCHI selection. Every model scored on every kind.

Then all twelve categories. The same design in every category at 25 objects per model — 36 models, each scored on 11,634 held-out trials from three kinds of each of twelve categories — and the analysis of Act 4 run on them unchanged.

Two honest limits. Inside a category the effect is small — a hundredth or two of margin, against a per-trial spread of two hundredths — and visible only with hundreds of trials and the trial held fixed. And the 16³ voxel distance is informative inside a category and uninformative between categories: at a matched distance from the training set, a same-category trial gains 0.07 and an other-category trial 0.02. On this descriptor the result is graded within a category and a step across categories, not one line. Whether a finer descriptor puts them on one line is the next analysis, and needs no new training.
Cost of the weekend: 60 fine-tunes and ~80 evaluations, about $530 unsubsidised / $115 subsidised. The first round (the agent's design) was $180 of it and showed nothing; the second (the lead's) showed the effect. The difference was not the metric but the experiment: a dose the training procedure can register, and a test set large and unselected enough to see it.
APPENDIX

Reproduce it

The whole analysis as a build specification. It assumes the 12 fine-tuned models and their ood_analysis_results.csv files already exist; if they don't, the fine-tune recipe is in Act 1. Copy this block into Claude with the data paths and it should be enough to re-implement the core result without reading any of our code.

GOAL
Test whether a model's oddity margin on a trial depends on the geometric distance between the
trial's objects and the model's training set, using a distance computed from 3D geometry alone
(no encoder), in a design where the trial is held fixed and only the training set varies.

INPUTS
1. MOCHI/mochi_trials.csv — 2,019 rows. Use columns: dataset, trial, oddity_index, images.
   `images` is a Python-literal list of filenames. For dataset == "shapenet", a filename is
   "<synset>_<modelid>_<view>.png" and the object key is "synset/modelid".
2. For each of 12 categories C (airplane 02691156, bench 02828884, cabinet 02933112,
   car 02958343, chair 03001627, display 03211117, lamp 03636649, loudspeaker 03691459,
   sofa 04256520, table 04379243, telephone 04401088, watercraft 04530566):
   ShapeNet_OOD_Analyses/C/ood_analysis_results.csv — 2,019 rows, positionally aligned to
   mochi_trials.csv. Use: fine_tuned_oddity_margin, pretrained_oddity_margin,
   fine_tuned_correct, pretrained_correct, d_AB_(L1_not_normalized).
   (Model C = DINOv2-L vit_large_patch14_reg4, LoRA r=16 α=8, multi-similarity loss,
   Adam 1e-6, 30 epochs, 20k triplets/epoch from rendered ShapeNet objects of category C
   only, MOCHI test objects excluded. Margin = mean over non-oddities of mean cosine
   similarity to the other images, minus the same for the oddity, on L2-normalised CLS.)
3. ShapeNet: model_normalized.solid.binvox (128^3) for every object in the 12 synsets.

STEP 1 — TRIALS
Keep shapenet trials in which every image has the same synset → 706 trials. Record each
trial's category ("own").

STEP 2 — BANK
All objects in the 12 synsets minus every object appearing in any MOCHI trial (897) →
20,885 objects. Bank for category C = its subset with synset C.

STEP 3 — DESCRIPTOR (voxel16; also run d57 and voxel8/32 for robustness)
Parse each binvox (RLE byte pairs after the "data" line; raw order x, z, y → transpose to
xyz). voxel16: reshape 128^3 → (16,8,16,8,16,8), mean over the three size-8 axes → 4,096
occupancy fractions.
d57 (rotation-invariant): occupied coords, subsample 4,096 (seed 0), centre, scale to unit
RMS radius; D2 = density histogram of 200,000 random pairwise distances, 32 bins on [0,4];
shell = density histogram of distance-to-centroid, 16 bins on [0,3]; plus 9 scalars
(elongation λ2/λ1, flatness λ3/λ1, compactness n_surface/n_vox^(2/3), convexity
(n_vox/rms^3)/hull_vol, norm_vol n_vox/rms^3, r_mean, r_std, d2_mean, d2_std).

STEP 4 — SHIFT, per (trial, category)
z-score each descriptor dimension with the bank mean/sd (sd<1e-9 → 1); L2-normalise rows.
For each test object: mean cosine distance (1 − dot) to its 50 nearest objects in bank C.
shift(trial, C) = mean of that over every image in the trial (never difference images).
→ 706 × 12 matrix X.
Also compute COVERAGE: −log(1 + #bank-C objects with cosine distance < 0.12 to the test
object), averaged over the trial's images. It is the better estimator (Act 7): higher
within-trial r and a pooled control near zero. Run both.
Entanglement check for any shift you build: r(shift, d_AB) across trials must be far
from 1. The manuscript's Eq. 1–3 form gives 0.99; do not use it.

STEP 5 — ASSEMBLE
Y[t, C] = fine_tuned_oddity_margin from file C at trial t. Also PRE (pretrained margin),
FC / PC (correct flags). Assert: within-trial sd of PRE, PC, d_AB is exactly 0.

STEP 6 — STATISTICS
a. Rank profile: rank X within each row; mean X, mean Y, SEM per rank. Expect Y to fall
   from ~0.17 (rank 1) to ~0.05 (rank 12); PRE constant across ranks.
b. Per-trial slope: Xc = X − rowmean, Yc = Y − rowmean; slope_t = Σ Xc·Yc / Σ Xc².
   Expect mean ≈ −0.17, ≈84 % of trials negative.
c. Permutation: 10,000×, permute each row of Xc independently, recompute mean slope;
   p = (1 + #null ≤ obs)/(N+1). Expect p ≈ 1e-4.
d. Cluster bootstrap: 2,000×, resample the 12 columns with replacement, recompute mean
   slope; 95 % percentile CI. Expect ≈ [−0.22, −0.03].
e. Trial-centred r over all 8,472: pearson(Xc, Yc) ≈ −0.33; pearson(Xc, PRE) = 0 exactly.
f. Accuracy by rank with FC: ≈ 81 % → 56 %; PC constant ≈ 51 %.
g. Transfer matrix: adv = Y − PRE; cell[i,j] = mean adv over trials with own == i under
   model j. Scatter 144 cells (x = mean shift, y = adv): r ≈ −0.36 all cells,
   ≈ −0.02 with the diagonal removed.

STEP 7 — THE SCOPE CHECK
Mask the on-category column (where C == own) and repeat 6b–6c on 11 points per trial.
Expect mean slope ≈ 0, p ≈ 0.3. The effect is a coverage effect; graded distance among
off-category training sets adds ~nothing.

STEP 8 — CONTROLS TO REPORT
(i) pooled r(X, PRE) on raw values is NOT zero (≈ −0.14): the pooled row contains object
atypicality. (ii) Within-trial it is zero by construction. (iii) Repeat 6b with d57 and
voxel8/32: expect 82–84 % negative under every descriptor. (iv) With COVERAGE in place of
knn_mean: within-trial r ≈ −0.41, pooled r(X, PRE) ≈ −0.03, 85 % of trials negative.
(v) With the ORIGINAL metric (trial_distance_(L1_not_normalized) per category file):
pooled r(X, PRE) ≈ +0.38 and on-category r(X, PRE) ≈ +0.61 — it fails the control in
every uncentred view and works only after two-way centring (trial-level r ≈ −0.45).
(vi) Any on-category effect must be re-tested after centring within category; the
coverage step (>100 neighbours) goes from binned r −0.78 to r = +0.03 when you do.

Not included. The human RT and accuracy relationships with geometric distance are left out. MOCHI's ShapeNet trials were selected adversarially, so a trial-geometry ↔ human-performance correlation may be a property of trial construction.
